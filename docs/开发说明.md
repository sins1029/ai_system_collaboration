# 开发说明

## 1. 当前开发状态

项目处于 Architecture A 冻结和最小可用版本审计阶段。默认工作是修复可复现性、路径、测试、文档和发布边界，不新增算法实验，不扩展 Architecture B/C 功能。

## 2. 代码所有权

- `src/sustaincluster_mpc/`：状态/动作适配与 MPC 求解。
- `src/sustaincluster_imitation/`：专家数据、因果预测、特征编码、BC 与权重桥接。
- `scripts/run_sustaincluster_demo.py`：唯一的 Architecture A 最小演示入口。
- `configs/sustaincluster_mpc/`、`configs/sustaincluster_imitation/`：冻结参数。
- `tests/`、`reports/sustaincluster_mpc/test_*.py`：主回归与 MPC 回归。
- `references/external_repos/`：只读参考，不纳入主项目版本控制。

不要在上游 SustainCluster 源码中修补路径。项目侧兼容逻辑应进入 `paths.py`、`environment_factory.py` 或适配器。代码目录位置不等于模块维护所有权：`environment_factory.py` 和 forecast interface/实现虽然物理上位于 `sustaincluster_imitation`，仍由环境与优化成员维护；学习算法成员只消费其稳定接口和 forecast feature，不并行修改实现。

## 3. 本地开发

安装：

```powershell
.\.venv-sustain-cluster\Scripts\python.exe -m pip install -e ".[research,test]"
```

编译检查：

```powershell
.\.venv-sustain-cluster\Scripts\python.exe -m compileall -q src scripts tests reports\sustaincluster_mpc
```

测试：

```powershell
.\.venv-sustain-cluster\Scripts\python.exe .\scripts\run_tests.py
```

短演示：

```powershell
.\.venv-sustain-cluster\Scripts\python.exe .\scripts\run_sustaincluster_demo.py --policy mpc --steps 5
.\.venv-sustain-cluster\Scripts\python.exe .\scripts\run_sustaincluster_demo.py --policy bc --steps 5
```

## 4. 代码规范与变更约束

- 使用 Python 类型标注；新增公共函数、类和非直观算法必须写中文 docstring/关键注释，变量和 API 保持英文命名。
- 新功能和缺陷修复必须带对应测试，不做与目标无关的全仓格式化。
- 新增路径必须从项目根目录推导，或由环境变量/CLI 参数传入。
- 统一使用 `SUSTAINCLUSTER_ROOT`；不要增加新的本机绝对路径。
- 用户可见注释、CLI、文档和项目自身错误信息优先中文；外部 API 字段、模型键和数据模式保持原名。
- 不修改经过冻结的目标权重、数据划分、特征顺序或动作语义，除非有独立审计与回归证据。
- 不让 oracle 数据进入主训练集。
- 不把训练动作混入演示入口。
- 不在导入模块时永久修改当前工作目录或全局随机状态。

## 5. 测试要求

路径与依赖变更至少覆盖：

1. `compileall`。
2. 根目录 `pytest -q`。
3. 5 步 MPC 演示。
4. 5 步 BC 演示。
5. 从非项目目录、通过 `SUSTAINCLUSTER_ROOT` 启动的迁移测试。

策略或适配器变更还要覆盖动作数量一致、动作合法、资源边界、环境只读快照、语义数据中心顺序和空任务状态。

## 6. 产物与 Git 边界

建议提交：源码、冻结配置、测试、中文文档、关键 Markdown 证据、默认 BC 检查点及其说明。

不建议提交：虚拟环境、外部仓库、`data/processed/`、SQLite 数据库、PPT 工作目录、批量 JSON/CSV/Parquet、LaTeX/PDF 中间产物、其他 seed 检查点、缓存和日志。

发布前只运行只读 Git 审计：`git status --short --branch`、`git diff --check`、`git diff --stat`、`git ls-files`。是否执行 `git add`、`commit`、`tag` 或远程操作由人工决定。

## 7. 三人分工

### 开发者 A：环境与优化

负责 SustainCluster integration、`environment_factory.py`、state/action adapter、MPC、constraint，以及 forecast interface 和实现。维护物理单位、资源边界、滚动时域状态、因果输入边界与上游兼容。

### 开发者 B：学习算法

负责 expert dataset、feature encoder、BC、regularized RL、policy，以及使用 forecast feature 的学习逻辑。维护特征/动作维度、checkpoint 谱系和 oracle 隔离，不直接修改 forecast 实现。

### 开发者 C：实验与评价

负责 experiment runner、metrics、evaluation、plots 和 regression。维护测试基线、结果摘要和发布清单。

三人都不能长期直接修改 `references/external_repos/sustain-cluster`。跨角色变更先明确输入输出契约，再修改实现。Architecture B 的事件触发校正只能插在语义决策与动作适配之间，不得绕开统一校验。

## 8. Git 协作

`main` 始终保持可安装、可测试、可运行 Demo。每项工作从最新 `main` 创建短期 `feature/xxx` 分支：

```text
main
  ↓
feature/xxx
  ↓
compileall + pytest + 对应 Demo
  ↓
pull request / code review
  ↓
main
```

第一版不使用复杂 Git Flow。提交前按模块分组审阅，不使用无差别暂存；合并由未直接实现该功能的人完成一次 code review。
