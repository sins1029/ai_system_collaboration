# 数据准备说明

## 1. 固定数据来源

Architecture A 的默认 workload 来自只读上游仓库 SustainCluster，固定版本为：

```text
repository: https://github.com/HewlettPackard/sustain-cluster.git
commit: 3f6ea95cb835b89ba50b0ef76d66d14b8037643e
```

该 commit 已跟踪预处理归档：

```text
data/workload/alibaba_2020_dataset/result_df_full_year_2020.zip
```

SustainCluster README 说明该归档由 [Alibaba Cluster Trace 2020](https://github.com/alibaba/clusterdata/tree/master/cluster-trace-gpu-v2020) 预处理并扩展为全年 15 分钟 workload。主项目不下载未经确认的第三方共享链接，也不把解压后的大型文件加入 Git。

上游 README 将原始 Alibaba 数据描述为限非商业研究并要求署名，同时要求使用者遵守各原始数据源条款。团队私有协作可按本说明复现；公开发布数据、模型或衍生产物前，仍需由项目负责人核对 Alibaba、SustainCluster 和实际使用场景的许可条件。本说明不替代法律审核。

## 3. 标准准备流程

先准备固定版本 SustainCluster；默认只克隆 Architecture A 必需的这一个外部仓库：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\clone_reference_repos.ps1
```

然后从上游已跟踪 ZIP 解压并校验：

```powershell
.\.venv-sustain-cluster\Scripts\python.exe .\scripts\prepare_workload.py
.\.venv-sustain-cluster\Scripts\python.exe .\scripts\prepare_workload.py --check
```

脚本只提取目标文件，并同时校验归档和 `.pkl` 的大小及 SHA256。校验失败会退出，不会接受静默的数据版本漂移。

## 4. 团队外部文件

如果上游 ZIP 暂时不可用，可以使用团队提供的同版本 `.zip` 或 `.pkl`，但仍必须通过固定校验值：

```powershell
$env:SUSTAINCLUSTER_WORKLOAD = "E:\team-share\result_df_full_year_2020.pkl"
.\.venv-sustain-cluster\Scripts\python.exe .\scripts\prepare_workload.py
```

也可以使用 `--source` 显式指定。`SUSTAINCLUSTER_WORKLOAD` 只表示输入来源；验证后的文件仍放到 SustainCluster 配置期望的位置。共享路径、凭据和访问令牌不得写入 Git。

## 5. Git 边界与错误处理

`references/external_repos/` 已由主项目忽略；上游仓库也忽略解压后的 `.pkl`。准备完成后，主项目和 SustainCluster 都应保持 clean。

缺失时，`--check` 会明确输出期望位置并指向本说明。不要把路径硬编码为个人目录，也不要从旧开发机手工复制而不做校验。
